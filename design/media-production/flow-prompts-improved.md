# Google Flow reference-led shot list

Reviewed against the local website on October 9, 2026, including the category-page changes at commit `bb21fe0`. This brief now assigns concrete reference inputs to every prompt. The original `prompts-archive/flow-prompts.md` is preserved. File / Type / Prompt columns and all 27 existing delivery filenames are retained. The optional Sphere still and clip are additional, unwired assets.

Rules for every shot: this is a guide to **actual Las Vegas**, including free experiences, family activities, shows, nightlife, pool parties, food, tours and transportation. Premium means strong photography and clear composition, not an empty luxury-only world. Preserve the recognizable destination, the real scale of its resorts, and the lively experience visitors are choosing. Upload the specifically named references before using a prompt. A source page is a selection/acquisition lead, not an attached image or video, and does not establish permission to republish or upload its media. Retain the geometry in a geographic reference; a motion reference supplies camera behavior only. Never import the older buildings, daylight, color grade or unrelated location from a motion clip. Generated editorial scenes retain the site's `Illustrative` caption and must not imply they document a named venue. Do not invent promotional text, signs, logos, events or identifiable people. Existing landmarks and signage in a real source are not a reason to invent an anonymous replacement city. Natural light, accurate materials and controlled highlights take precedence over a uniform violet/amber grade. Retain platform-required provenance marks.

Framing is specific to the website: category tiles are **4:5**, with a quiet lower quarter for the bottom-left label and some upper-right space for the caption. Desktop hero is **16:9**, mobile hero **9:16**. Use a real Strip composition that works with the bottom-left headline and the site's gradient; do not relocate or resize landmarks to fit text. Portrait tablets currently receive the desktop source, so test the actual center-cover crop and use a separately composed source where needed. Listing photos are **4:3** in the executable CSS. Story **4:5 is a proposed master format**, pending the unbuilt story layout. OG export is exactly **1200 x 630**.

The current code reuses each portrait `band-*.jpg` as a wide category-page header. At a 1440 x 900 viewport, that header is about 1440 x 468 and retains only the central 26% of the portrait image's height. The preferred production approach is separate portrait tiles and landscape headers, with the eight additional prompts below. Those new header filenames require a small loader change before they display. Until then, each band must survive both crops: keep its essential subject around 40-55% down the portrait frame and preview the wide crop before final export. Do not assume a good tile automatically makes a good page header.

Set ratio, duration, model and resolution in Flow's controls. If the image model does not offer 4:5, use its nearest portrait option and crop to 4:5 without cutting the subject; words in a prompt do not set file dimensions. Generate 2 composition candidates first, select the stronger one, then make targeted refinements. Keep the best full-resolution masters outside the website delivery folder. Export approved delivery files to `assets/media/` only when ready to integrate them.

**Reference inputs and approval order:** resolve every ID through [reference-manifest.csv](reference-manifest.csv) and [reference-guide.md](reference-guide.md); check its local-file and approval status before uploading. `USER-STRIP-01` is attachment #1, the south-Strip blue-hour photograph with Mandalay Bay at left and MGM Grand at right. `USER-SPHERE-NIGHT-02` is attachment #2 and controls the Sphere shot's entire camera view, nighttime exposure, building geometry and surrounding city. `USER-SPHERE-FACE-03` is attachment #3 and supplies only the yellow LED face design: its eyebrows, eyes and small smile. Its daylight sky, viewpoint and foreground must not transfer. The local `GEN-SPHERE-01` composite is a candidate, not an approved starting frame; inspect it against both supplied Sphere images first. `REF-*` IDs identify the concrete photographs in the accompanying reference catalog. Remote references require an acquired, usable local file before generation.

`DERIVED-HERO-POSTER` means the approved `hero-poster.jpg`; `DERIVED-HERO-MOBILE-FRAME` means an approved 9:16 crop of the same real south-Strip scene, prepared before generating `hero-mobile.mp4`. `DERIVED-BAND-SHOWS`, `DERIVED-BAND-FREE`, `DERIVED-BAND-FOOD`, `DERIVED-BAND-NIGHTLIFE`, `DERIVED-BAND-POOLS`, `DERIVED-BAND-TOURS`, `DERIVED-BAND-TRANSIT` and `DERIVED-BAND-21PLUS` mean the corresponding approved `band-*.jpg` outputs. **Models and input modes:** use **Nano Banana Pro** to combine or edit the reference images and prepare the stills. Use **Veo 3.1 Quality, Frames to Video** for the alternate route with the approved image as the starting frame and motion described in text. Veo 3.1 Quality's frame route does not take the several reference images or the sample video as those inputs. In that route the sample video is a visual brief reviewed by the operator, and only the approved scene frame is uploaded. Model availability, export resolution and input limits must be checked in the active Flow account. Reference inputs improve control; none of these models guarantees accurate buildings or camera paths.

## Delivery and selection notes

- **Proposed output sizes:** keep high-quality masters; export category tiles and story JPEGs at 1200 x 1500, optional landscape headers and desktop poster at 1920 x 1080, real listing photos at 1200 x 900, and OG at 1200 x 630. Desktop video at 1600 x 900 or 1920 x 1080 and mobile at 720 x 1280 or 1080 x 1920, depending on what Flow actually supplies. Never upscale just to satisfy a label. Export sRGB images and preserve a consistent final color treatment. These are delivery targets, not model promises.
- **Web video:** H.264 MP4, compatible pixel format, no audio track, web fast-start metadata. The original CRF 28 command cannot guarantee an output under 2 MB. An 8-second file capped at 2,000,000 bytes has a theoretical total average budget of 2.0 Mb/s; use a lower video target to allow container overhead, or accept a larger file after checking visible quality. CRF chooses quality rather than a fixed size. Keep masters and compare actual encoded results before choosing the site's budget.
- **Image selection:** check the native 4:5 crop, the centered tablet hero crop and the 390px mobile hero with the site's real text overlaid. Reject unstable architecture, implausible aircraft/track geometry, distorted anatomy or food, smeared reflections, crushed dark areas, clipped lights and accidental lettering. Retain purposeful depth and natural detail rather than adding sharpening or stronger neon.
- **Attribution:** Generated category and story scenes remain labeled `Illustrative`. A source URL in listing data is not a photography license. Named venue cards should use actual authorized photography or publicity assets; their acquisition briefs and proposed paths are tracked in `listing-media-plan.csv`. A neutral text-led card is preferable to a fake venue image.
- **Listing mapping:** for a file at `assets/media/listings/bellagio-fountains.jpg`, the listing's `image` value is `listings/bellagio-fountains.jpg`, with an appropriate `image_credit` for a real authorized photo. The loader supplies the `assets/media/` prefix. Adding a full local delivery path to `image` would duplicate that prefix. The loader currently does not check file existence, so verify the final path and credit when integrating it. Adult listing cards remain text-only under the current renderer.
- **Motion:** one ambient hero is sufficient for the present page. Category cards work as stills with the existing lightweight UI motion; the proposed story can use quiet crossfades when built. Additional background videos would increase transfers and visual competition without adding useful content.
- **Coverage:** the map needs sourced coordinates and an SVG implementation, rather than an AI picture of geography. FAQ, filters, age confirmation and the 404 page do not require new generated imagery. The listing CSV covers all 257 records, including closed/unconfirmed/text-only entries; it is an acquisition plan rather than 257 synthetic venue-photo requests. The primary Eat image now reflects the page's Indian/vegetarian emphasis; the dinner story keeps a different dish for visual variety.
